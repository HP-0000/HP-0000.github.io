###### 소멸자 코드의 생성
컴파일러는 객체의 유효 스코프가 끝나는 지점에 일반적인 소멸자 호출 코드를 작성한다.
추가적으로 `throw` 대비 함수 끝단에 비상 정리 코드인 랜딩 패드(Landing Pad)를 만들고, 
이를 가리키는 예외 테이블(Exception Table)을 바이너리 내부에 정적으로 심어둔다.
###### 예외 테이블(Exception Table)
- 키 (Key): 예외가 발생할 수 있는 코드의 주소 범위 (PC Range)
	- try 블록 내부 구간
    - 지역 객체의 유효 생명주기 구간 (생성자 호출 완료 직후 ~ 소멸 직전)
- 값 (Value): 랜딩 패드(Landing Pad)의 시작 주소
###### 랜딩 패드(Landing Pad)
예외가 발생하여 CPU 제어권이 해당 주소로 점프했을 때 순차적으로 수행하는 정리 작업.

1. 스택 정리 (Clean-up)
    해당 시점까지 살아남은 지역 객체들의 소멸자를 역순(LIFO)으로 호출하여 
    메모리와 자원을 해제한다.    
2. 흐름 제어 (Dispatch):
    던져진 예외의 타입과 일치하는 catch 블록이 있다면 해당 catch 핸들러로 진입한다.
    일치하는 catch가 없다면  `_Unwind_Resume()`을 호출하여 현재 스택 프레임을 파괴하고 
    호출자의 리턴 주소를 얻어 상위 스택으로 이동한 뒤 이 과정을 반복한다.
###### `throw` 발생 시 런타임 동작
1. throw가 예외 객체를 던지면, C++ 런타임 시스템이 현재 충돌이 발생한 PC(명령 포인터) 주소를 
   키(Key)로 삼아 예외 테이블을 검색하고  랜딩 패드를 호출한다.
2. catch 핸들러 이후 정상 실행 흐름으로 복귀한다.
###### 처리되지 않은 예외 (Unhandled Exception)
최상위 호출 스택까지 모두 언와인딩되었음에도 일치하는 catch 블록을 전혀 찾지 못하면
런타임 시스템이 `std::terminate()`를 호출하여 프로그램을 비정상 강제 종료한다.

[noexcept](Public/Study/C++/Docs/Compile/noexcept.md) 가 붙은 함수 내부에서 예외가 처리되지 못하면
C++ 런타임은 즉시 `std::terminate()`를 호출하여 프로그램을 종료시킨다.
