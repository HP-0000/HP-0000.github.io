컴파일러의 템플릿 컴파일 동작 방식이다.

[템플릿특수화](/Public/Study/C++/Docs/템플릿_특수화)
템플릿 코드를 컴파일하는 경우 우선순위에 따라 특수화된 후보들에
구체적인 타입을 템플릿 인자에 넣어 치환해본다.

[인자 타입 추론](Public/Study/C++/Docs/인자%20타입%20추론.md)

이때 오류가 발생하더라도, 곧바로 컴파일 에러를 발생시지 않고 
해당 템플릿 후보 목록에서 제외한 뒤 다음 후보를 찾아 반복한다.

모든 템플릿 후보를 일일이 검사한 이후,  가장 적합해 보이는 후보를 선택한다.
우선 순위가 동일하다고 판단되면 컴파일 에러를 발생시킨다.

컴파일러의 이러한 동작 규칙을 이용하여
타입에 따른 코드 분기를 컴파일 타임에 구현할 수 있다.
### Example

```cpp
template <typename T, typename = void>
struct example 
```
기본 템플릿을 작성한다. 두번째 인자에 기본값을 명시하였다.

```cpp
example<T> x;
```
컴파일러는 이를 `example<T, void>`로 해석한다.

```cpp
template <typename... Args> 
using void_t = void;
```
인자가 유효한 타입이기만 하면 `void` 타입의 별칭을 선언한다.

```cpp
template <typename T>
struct example<T, void_t<typename T::Value>>
```
두번째 인자를 명시함으로서 특수화된 템플릿이다.

```cpp
example<T> x;
```
`T::Value` 가 존재한다면 특수화된 템플릿이 구현된다.
`T::Value` 가 존재하지 않는다면 기본 템플릿이 구현된다.

---

SFINAE 의 동작은 다음의 문제들을 유발했다.

컴파일러가 템플릿 후보를 일일이 대입함으로 컴파일 속도가 느려진다.
템플릿 치환 실패시 컴파일러가 방대한 실패 로그를 만들어 내어 원인을 분석하기 어렵다. 
템플릿 선언만으로는 내부 코드를 확인하기 전까지 어떤 타입과 값을 의도하여 만든 것인지 알 수 없다.
또한 인자 자리에 또 다른 템플릿을 중첩해서 쑤셔 넣음으로서 코드가 기괴해지고 
유지보수가 매우 어려워진다.

이러한 이유로 C++20 이후 [Concept](Public/Study/C++/Docs/Concept.md)가 도입된다.
