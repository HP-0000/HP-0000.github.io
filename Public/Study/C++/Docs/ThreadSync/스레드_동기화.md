# 동기화 알고리즘의 성능과 확장성

![](Resource/Pasted%20image%2020260502025824.png)

스레드를 사용할 때 성능에 가장 직접적인 영향을 주는 것은 캐시 라인의 무효화다. 
읽기는 캐시 라인이 유지되며 병렬화 할 수록 성능은 증가한다. 
쓰기의 경우 작업이 무거워 읽기 보다는 느리고, 만약 공유 자원에 대해서 쓴다면 
캐시라인이 무효화 되기 때문에 성능이 더 나빠진다.
#### 거짓 공유
관계 없는 두 데이터가 주소가 가까이 있다는 이유로 하나의 캐시라인으로 묶여 있어  
멀티 스레드에서 캐시라인의 무효화가 발생하여 성능 하락을 유발함. [Alignment](Public/Study/C++/Docs/Alignment.md)
#### 비트 쪼개기 전략
하드웨어의 원자적 연산이 해결하는 공간은 하나지만 각 비트에 여러 개의 상태를 집어넣음으로써
독립된 논리를 단 한 번의 원자적 연산으로 동시에 갱신하는 전략이다.
### CPU 코어 동작 이해

#### MESI 프로토콜

캐시 일관성을 위해 각 캐시라인이 갖는 상태
- M (Modified) : 나만 이 캐시를 가지고 있고, 메모리보다 최신 값임. (수정됨)
- E (Exclusive) : 나만 이 캐시를 가지고 있고, 메모리와 값이 같음. (독점)
- S (Shared) : 다른 코어도 이 캐시를 가지고 있고, 메모리와 값이 같음. (공유)
- I (Invalid) : 이 캐시 라인은 무효화됨. (읽으면 캐시 미스 발생)

###### 현재 코어의 캐시 읽기 명령에 대해
현재 코어의 해당 캐시라인이 `I` 상태인 경우 다른 코어들에 `BusRd` 신호를 보낸다.
`BusRd` 신호를 받은 코어들은 만약 해당 캐시가 없는 경우 `Snoop Mis` 응답을 보낸다.
모든 응답이 `Snoop Mis` 라면 L3 캐시(또는 RAM) 로 부터 데이터를 수신하여 캐시라인에 덮어 쓰고 상태를 `E`로 변경한다.

`BusRd` 신호를 받은 코어들은 만약 해당 캐시가 있는 경우 `Snoop Hit` 응답을 보내고 `M` 상태인 코어는 데이터도 함께 싣는다. 코어들은 캐시라인을 `S` 상태로 변경한다.  

`Snoop Hit` 응답을 확인한 현재 코어는 L3 캐시(또는 RAM)으로 부터, 또는  `M` 상태인 코어로부터 
수신된 데이터로 캐시라인에 덮어 쓰고 상태를 `S`로 변경한다.

`Retry` 응답을 받는 경우 코어는 잠시 `Stall` 후 재시도 한다.

###### 현재 코어의 일반 캐시 쓰기 명령에 대해

현재 코어의 해당 캐시라인이 `S` 상태인 경우 다른 코어들에 `Upgrade` 신호를 보낸다.
`Upgrade` 신호를 받은 코어들은 캐시라인을 `I` 상태로 변경 한 뒤 완료 응답(`ACK`)을 보낸다.
모든 코어로 부터 `ACK`를 확인한 현재 코어는 캐시라인 쓰기를 수행하고 `M`으로 변경한다. 

현재 코어의 해당 캐시라인이 `I` 상태인 경우 다른 코어들에 `Read For Ownership` 신호를 보낸다.
`RFO` 신호를 받은 코어 중 `M` 상태를 가진 코어가 있다면 그 코어가 직접 캐시라인 데이터를 전송하고
`M` 상태를 가진 코어가 없는 경우는 L3 캐시(또는 RAM)이 데이터를 해당 코어로 전송한다.
`RFO` 신호를 받은 코어는 해당 캐시라인을 `I` 상태로 변경하고 완료 응답(`ACK`)을 보낸다.  
데이터 수신 및 모든 `ACK`를 확인한 현재 코어는 수신된 데이터에 쓰기 명령을 수행한뒤 캐시라인에 덮어 쓰고 상태를 `M`으로 변경한다.

`Retry` 응답을 받는 경우, `Store Buffer`에 쓰기가 일어나며 코어는 `Stall` 없이 잠시 후 재시도 한다.
######  Invalid Queue
코어가`I` 상태로 변경 작업을 수행하기 위해서는 정지해야 함으로  성능을 위해 
`Invalid Queue` 에 메시지를 넣어두고 실제 처리를 미룬다. 

`Invalid Queue` 에 메시지가 존재하며 신호를 수신 받는 경우,
`Read For Ownership` 또는 `Upgrade`신호를 수신하는 경우 `ACK` 응답을 보내고 
`BusRd` 신호를 수신하는 경우 `Snoop Miss` 응답을 보낸다. 
`Invalid Queue`가 가득 차면 `Retry` 로 응답한다.

`Invalid Queue` 에 메시지가 존재하며 신호를 보내는 경우,
`BusRd` 신호는 메시지를 꺼내 코어 무효화를 처리한 이후 보낸다.
`Upgrade` 신호는 `RFO` 신호로 변경된다.
`RFO` 신호는 메시지를 꺼내 무시한뒤  보낸다.

코어에 여유가 생기면 `Invalid Queue`에서 메시지를 꺼내 해당 캐시라인을 `I` 상태로 변경한다.
######  Store Buffer
코어는 쓰기를 수행하기 위해 `ACK` 응답을 기다려야 하지만 성능을 위해 
`Store Buffer`에 먼저 기록한다.  `Store Buffer`가 가득차면 정지하낟.

방금 기록한 값을 읽어야 하는 상황이라면, 캐시가 아닌 `Store buffer`에서 읽어온다.
`ACK` 응답을 받으면 그제서야 `Store Buffer` 값을 캐시 라인에 업데이트 한다.

먼저 도착한 `ACK`부터 처리하거나 동일 캐시라인에 대한 쓰기를 묶어서 처리하는 최적화로 인해 
실제 캐시라인에 반영되는 순서는 코드 순서와 다르게 뒤바뀔 수 있다.
###### 현재 코어의 Read-Modify-Write 명령에 대해 
원자적 연산을 수행하기 위해 코어는 `Invalidation Queue` 의 메시지를 처리 한 뒤 
신호를 보내 응답을 수신할 때 까지 `Stall` 되어 모든 신호에 대해 `Retry` 로 응답한다.  응답이 수신 되면 `Store Buffer`를 거치지 않고  캐시라인에 대해 직접 원자적 연산을 수행한 뒤 `M` 상태로 변경한다.

현재 코어의 해당 캐시라인이 `I` 상태인 경우
코어는 `RFO` 신호를 보내 `ACK` 응답 및 데이터를 수신한다.

현재 코어의 해당 캐시라인이 `S` 상태인 경우
`Upgrade` 신호를 보내`ACK` 응답을 수신한다.

현재 코어의 해당 캐시라인이 `M` , `E` 상태인 경우 즉시 실행한다.

###### 메모리 배리어 
컴파일러와 cpu 최적화에 대해
코어간 서로 다른 캐시라인의 명령어 순서와 가시성을 보장하기 위한 명령
###### LoadLoad
읽기 명령이 수행된 이후 Invalidate Queue 의 전체 메시지를 처리하기 까지
이후의 읽기 명령을 `Stall` 한다.
###### LoadStore
읽기 명령이 수행이 완료될 때까지, 
이후의 쓰기 명령 결과가 캐시에 커밋 되는 것을 `Stall` 한다.
###### StoreStore 
쓰기 명령 결과가 캐시에 커밋될 때까지, 
이후의 쓰기 명령 결과가 캐시에 커밋 되는 것을 `Stall` 한다.
###### StoreLoad
쓰기 명령 결과가 캐시에 커밋될 때까지, 
이후의 읽기 명령을 `Stall` 한다.
