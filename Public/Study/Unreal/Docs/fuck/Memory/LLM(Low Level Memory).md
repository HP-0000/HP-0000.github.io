###### LLM의 목적 및 동작 방식
* **목적:** 태그(Tag) 단위로 세밀한 메모리 사용량을 추적하기 위해 도입되었습니다.
* **추적 방식:** `Scope` 객체를 활용해 추적할 태그 범위를 지정하며, `new` 연산자 오버로딩을 통해 `FLowLevelMemTracker`가 메모리 할당 및 해제 내역을 직접 기록합니다. 

* **동작 방식:** 스레드별로 State 객체를 활용해 태그별 메모리 증감 수치를 락(Lock) 없이 빠르게 관리하며, 이와 동시에 메모리 해제(Free) 추적을 위해 전역 해시맵(Global HashMap)에 할당된 메모리 주소를 Key로, 태그와 사이즈를 Value로 삼아 관리한다.
######  메모리 분리 및 FLLMAllocator
* FLowLevelMemTracker 내부적으로 사용하는 할당기. 
* OS로부터 페이지(Page) 단위로 메모리를 직접 할당받아 내부적으로 쪼개어 사용.
* 할당기 자체의 메모리 사용은 단순히 LLMMallocTotal 숫자로 관리 된다.
######  FLLMAllocator의 내부 계층 구조
* **`FBin` (사이즈별 관리):** 다양한 크기의 메모리를 효율적으로 할당하기 위해 구간(Size Class)별로 할당풀을 관리합니다. 전체 구조는 여러 `FBin`을 담은 배열 형태로 이루어집니다.
* **`FPage` (페이지 관리자):** `FBin`은 OS로부터 할당받은 페이지를 관리구간 크기 단위의 '블록(Block)'들로 나눕니다. 이때 페이지의 맨 앞부분 블록을 할애하여 해당 페이지를 통제하는 관리자 객체인 `FPage`를 배치합니다. `FPage`들은 이중 연결 리스트(Doubly Linked List)로 연결되어 관리됩니다.
* 블록(Block) 단위 관리 메커니즘:
  * **주소 역산:** 각 블록의 포인터 주소에 비트 마스킹(Bit Masking) 연산을 적용하면, 자신이 속한 페이지의 맨 앞에 위치한 `FPage` 관리자의 주소를 즉시 찾아낼 수 있습니다.
  * **메모리 최적화:** 현재 사용 중이지 않은 빈 블록(Free Block)들은 내부 공간에 링크드 리스트의 다음 포인터(`Next`)를 직접 저장합니다. 어차피 비어있는 공간을 활용하므로 추가적인 메모리 낭비 없이 효율적으로 관리됩니다.
