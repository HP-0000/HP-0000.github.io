## Ring이란?
Intel이 CPU 하드웨어 레벨에서 설계한 권한 레벨 개념. OS가 만든 개념이 아니라 CPU가 제공하는 메커니즘이다.
ARM에서는 Exception Level(EL0~EL3)이라고 부른다.
## CPU가 아는 것 / 모르는 것

| CPU가 아는 것                   | CPU가 모르는 것       |
| --------------------------- | ---------------- |
| 현재 Ring 레벨 (CS 레지스터)        | "커널 코드", "유저 코드" |
| PTE(Page Table Entry) 권한 비트 | "커널 공간", "유저 공간" |
| 다음 실행할 명령어                  | 코드의 의미와 목적       |
커널/유저 공간의 구분은 **OS가 페이지 테이블을 통해 만든 추상화**다.

RAM
┌──────────────────────────────┐
│  커널 공간 주소 범위          │
│  ┌────────────────────────┐  │
│  │  커널 코드 (OS 코드)    │  │← 실제로 여기 저장됨
│  │  커널 데이터, 스택 등   │  │   PTE U/S = 0
│  └────────────────────────┘  │
├──────────────────────────────┤
│  유저 공간 주소 범위          │
│  ┌────────────────────────┐  │
│  │  유저 프로그램 코드     │  │← 실제로 여기 저장됨
│  │  유저 데이터, 스택 등   │  │   PTE U/S = 1
│  └────────────────────────┘  │
└──────────────────────────────┘

> CPU는 메커니즘 을 책임지고, OS는 정책(무엇을 허용할지)을 책임진다.

---
## 부팅 흐름
```
전원 ON → CPU는 Ring 0 상태로 시작
       → BIOS/UEFI 실행 (Ring 0)
       → OS 로드 (Ring 0)
       → OS가 유저 프로그램을 Ring 3으로 제한하여 실행
```

OS는 Ring 0 권한을 가진 첫 번째 프로그램으로, **스스로 Ring 0 사용을 제한하는 규칙을 만들고 강제하는 존재**다.

## 로컬 환경의 한계

물리적으로 본인 컴퓨터에 접근 가능하다면 Ring 0 획득이 가능하다.

```
Secure Boot 끄기 (BIOS 설정)
       ↓
커스텀 OS 부팅
       ↓
Ring 0 획득 → 모든 메모리 접근 가능
```

Ring 0를 가진 경우 로컬에서 돌아가는 모든 프로그램은 원칙적으로 노출된다.

> 로컬 머신의 주인은 그 머신의 모든 것을 볼 수 있다. 이는 소프트웨어로 막을 수 없는 근본적인 한계다.

그래서 현대 보안의 방향은 **"로컬을 절대 신뢰하지 않는다 (Zero Trust)"** 이며, 중요한 로직과 검증은 모두 서버에서 처리하는 구조로 이동하고 있다.
