GPU는 제어 장치와 캐시 메모리를 줄이는 대신 연산 코어를 더 늘려 놨다.
병렬로 대규모의 연산을 처리 하도록 설계 된 것이다.

![](/Public/Study/컴퓨터%20구조/Docs/GPU/Resource/Pasted%20image%2020260529190337.png)

연산기인 코어(Core)들을 수십~백여 개 묶어서 스트리밍 멀티프로세서(SM)을 만든다.
그리고 SM들을 여러 개 묶어서 그래픽 처리 클러스터(GPC)를 만든다.
그리고 GPU는 GPC의 집합이다.

![](/Public/Study/컴퓨터%20구조/Docs/GPU/Resource/Pasted%20image%2020260529191546.png)


스레드를 묶어 블록, 블록을 묶어 그리드를 만든다.
블록과 그리드는 1차원, 2차원 또는 3차원으로 만들 수 있다.

각 스레드는 3차원 벡터 내장 변수를 통해 자신의 위치를 계산 할 수 있다.
- `threadIdx` (스레드 인덱스): "내가 **블록 내부**에서 몇 번째 일꾼인가?"
- `blockIdx` (블록 인덱스): "내가 속한 블록이 **그리드**에서 몇 번째 방인가?"
- `blockDim` (블록 치수): "우리 블록은 총 몇 차원이고 스레드가 몇 개씩 들어있나?"
- `gridDim` (그리드 치수): "이 전체 작업(그리드)은 블록이 몇 개나 쌓여있나?"


블록 내의 모든 스레드는 워프 단위로 묶여 동일한 SM에서 동시에 실행되며 
블록은 사용 가능한 GPC 의 SM에 분산 되어 순서 보장 없이 실행된다.
같은 블록 내의 스레드들 간에는 SM 내부의 온칩 공유 메모리에 접근 가능하다.

![](/Public/Study/컴퓨터%20구조/Docs/GPU/Resource/Pasted%20image%2020260529195317.png)

스레드 블록을 묶어 클러스터를 지정할 수 있다.
클러스터 내의 블록들은 동일한 GPC에서 사용 가능한 SM에 분산 되어 동시에 실행된다.
클러스터 내의 블록 간 스레드들은 다른 SM들의 온칩 메모리 즉 분산 공유 메모리에 접근 가능하다.

#### SIMT(Single-Instruction Multiple-Threads)

블록 내에서 스레드는 워프 라고 불리는 32개 스레드 그룹으로 구성된다.
워프내의 모든 스레드(레인)은 동시에 같은 명령어를 실행하게 된다.

![](/Public/Study/컴퓨터%20구조/Docs/GPU/Resource/Pasted%20image%2020260529204809.png)

워프 내에서 만약 분기가 발생하는 경우,  조건을 만족하는 스레드가 실행 되는 동안 나머지는 마스크 처리되어 대기한다. 실행이 끝나면 활성 마스크를 변경하여 다른 경로의 스레드를 실행한다. 따라서 워프 내의 모든 스레드가 동일한 제어 흐름(Control Flow)을 따를수록 GPU 활용도가 최대화된다.

#### Tile 
타일은 블록에 국한되는 다차원 값이다. 연산을 하면 새로운 타일 값이 나온다.
SIMT 와 달리 그리드 크기 만을 지정하면 타일 연산을 기반으로 컴파일러가 블록 당 스레드 수를 결정한다.

SIMT는 개별 스레드에 대한 세밀한 제어를 제공하며 행렬과 같은 요소별 계산에는
타일 프로그래밍을 통해 하드웨어 최적화된 계산이 가능하다.

---

#### 메모리 구조
VRAM은 모든 SM이 접근 가능한 전역 메모리다.
SM은 레지스터 파일과 공유 메모리를 가지고 있다.
레지스터 파일에는 컴파일러가 할당한 스레드 지역 변수가 저장되며
공유 메모리는 블록 또는 클러스터 내의 모든 스레드가 접근 할 수 있다.
