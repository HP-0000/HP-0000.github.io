
###### x86 / x86-64 (인텔, AMD)
- 강한 메모리 모델(TSO: Total Store Order)을 사용한다.
- 하드웨어 차원에서 대부분의 명령어 재배치를 엄격히 금지하므로 칩 회로가 복잡하고 전력 소모가 크다.

###### ARM / ARM64 (애플 M시리즈, 모바일, AWS Graviton)
- 약한 메모리 모델(Weakly Ordered)을 사용한다.
- 전력 소모를 줄이고 처리 속도를 극대화하기 위해 하드웨어의 자유로운 재배치를 허용하며, 개발자가 명시적으로 요청할 때만 이를 통제한다.

###### 하드웨어의 명령어 재배치(Reordering) 허용 범위
CPU 파이프라인 및 스토어 버퍼 최적화 과정에서 하드웨어가 선행/후행 명령의 처리 순서를 
변경할 수 있는지에 대한 아키텍처별 규격

[스레드_동기화](Public/Study/C++/Docs/ThreadSync/스레드_동기화.md)

| 재배치 유형               | x86 (인텔/AMD) | ARM (애플/모바일) | 하드웨어 동작 정의                                  |
| :------------------- | :----------: | :----------: | :------------------------------------------ |
| **Load-Load (LL)**   | ❌ **절대 금지**  |   ⭕ **허용**   | **선행 읽기**가 완료되기 전에 **후행 읽기**를 먼저 실행         |
| **Load-Store (LS)**  | ❌ **절대 금지**  |   ⭕ **허용**   | **선행 읽기**가 완료되기 전에 **후행 쓰기** 결과가 캐시에 먼저 커밋  |
| **Store-Store (SS)** | ❌ **절대 금지**  |   ⭕ **허용**   | **선행 쓰기**가 캐시에 커밋되기 전에 **후행 쓰기**가 캐시에 먼저 커밋 |
| **Store-Load (SL)**  |   ⭕ **허용**   |   ⭕ **허용**   | **선행 쓰기**가 캐시에 커밋되기 전에 **후행 읽기**를 먼저 실행     |
